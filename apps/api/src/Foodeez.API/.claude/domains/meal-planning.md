# Domain: meal-planning

## Purpose

The weekly meal calendar: a plan covering a date range, with one or more entries per day and
meal type, filled in by hand or generated by the AI from the user's profile and history.

## Main Flows

**Read / create** - `GET api/meal-plans` (by range), `POST api/meal-plans`.

**Entries** - `POST api/meal-plans/{planId}/entries`,
`PUT api/meal-plans/{planId}/entries/{entryId}`,
`DELETE api/meal-plans/{planId}/entries/{entryId}`. An entry points at either a `Recipe` or a
`FoodItem` (both nullable) with `Servings` and optional notes.

**Slot rules live on the entity.** `MealPlan.Covers(date)` and
`MealPlan.OccupantsOf(date, mealType, exceptId)` are what the use cases ask before accepting an
entry - a date outside the plan, or a slot already occupied, is refused with a `Failure(...)`
`ProblemDetails` carrying a reason the client can show.

**AI generation** - `POST api/meal-plans/generate` (blocking) and
`POST api/meal-plans/generate/stream` (SSE). `GenerateAIMealPlanUseCase` loads the profile,
attaches the previous period for context via `PlannedMealReader`, builds the prompt with
`MealPlanPrompt` (one builder for both paths, not per-provider), and streams narration plus the
finished plan. Plans it creates are marked `IsAIGenerated`.

## Data and State

`MealPlans` (user, name, `StartDate`/`EndDate` as `date`, `IsAIGenerated`) and
`MealPlanEntries` (`EntryDate`, `MealType`, nullable `RecipeId` / `FoodItemId`, `Servings`,
notes). The grocery list for a range is compiled from these entries - see `domains/grocery.md`.

## External Systems

## Known Gotchas

- The planner used to issue one query per meal; the reads are now batched and no-tracking
  (commit `389a2be`). Do not reintroduce a per-entry query inside a loop.
- A rejected slot must return `Failure(...)`, not a bare string - the mobile client only shows
  `detail` / `title`, which is why rejected slots once said nothing about why.
- `MealPlanPrompt` is shared by the blocking and streaming paths on purpose; adding a
  provider-specific prompt builder would let them drift.
- `EntryDate`, `StartDate` and `EndDate` are `DateOnly`, mapped to `date` columns.
