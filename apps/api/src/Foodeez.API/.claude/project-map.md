## Purpose

Foodeez is an AI-assisted food tracking and meal prepping application. Users log meals (by
hand, by photo, or by free-text quick-add), get nutrition breakdowns and AI analysis, chat
with an AI nutrition assistant, plan a week of meals on a calendar, and compile a grocery
list from that plan. One .NET backend serves two clients: a Vue web app and a React Native
(Expo) mobile app.

## Entry Points

- **API** - `apps/api/src/Foodeez.API/Program.cs`; listens on `http://0.0.0.0:5000`.
  Swagger at `/swagger` (Development only), health check at `/health`.
- **Web** - `apps/web/src/main.ts` then `App.vue`; dev server on port 3000, proxies `/api` to
  `http://localhost:5000` (`apps/web/vite.config.ts`).
- **Mobile** - `apps/mobile/index.js` then `App.tsx` then `src/navigation/RootNavigator.tsx`.
- **Shared** - `packages/shared/src/index.ts` (re-exports enums, types, constants, utils).
- **Everything at once (Windows)** - `start-all.bat` opens three terminals.
- **Background work** - `LogWriterService` (`IHostedService`) drains the in-memory log queue
  into the `AppLogs` table.

## Configuration and Secrets

- Non-secret configuration is committed in `apps/api/src/Foodeez.API/appsettings.json`
  (model names, provider base URLs, token ceilings, log levels, CORS list, Kestrel URL).
- Secrets come from **.NET user-secrets in Development** and **environment variables when
  deployed** (`:` becomes `__`, e.g. `Jwt:Key` becomes `Jwt__Key`). `docker-compose.yml` feeds
  those from a `.env` file; `.env.example` is the template.
- Required at startup or the API refuses to boot, naming the key: `ConnectionStrings:Default`,
  `Jwt:Key` (at least 32 chars), `Jwt:Issuer`, `Jwt:Audience`.
- Provider API keys are deliberately *not* required at startup, because the active provider is
  chosen at runtime from the database.
- Some settings are runtime, not file-based: the `AppSettings` table drives `ai.provider` and
  `local.*` overrides, editable from Admin > Settings.
- Mobile: optional `apps/mobile/.env` with `EXPO_PUBLIC_API_URL` (must include the `/api` suffix).
- **Never put a secret in `appsettings.json`, `.env.example`, or any memory file.**

## Data and State

- MySQL 8.4 via EF Core. 13 migrations in `apps/api/src/Foodeez.Infrastructure/Migrations/`,
  `InitialCreate` through `AddChatSuggestedRecipes`.
- 19 `DbSet`s on `AppDbContext`: users/profiles, food items, meal logs + items, day analyses,
  meal templates + items, recipes + ingredients, saved recipes, meal plans + entries, chat
  conversations + messages, grocery lists + items, app logs, app settings.
- All entities derive from `BaseEntity` (client-assigned `Guid Id`, `CreatedAt`, `UpdatedAt`).
- Repositories plus `IUnitOfWork` sit between use cases and EF; `UnitOfWork.SaveChangesAsync`
  translates `DbUpdateConcurrencyException` into `ConcurrencyConflictException` (HTTP 409).
- Client state: Pinia (web, token in `localStorage` under `foodeez_token`) and Zustand
  (mobile, token in `expo-secure-store`).
- Auto-migration on startup: on in Development, otherwise opt in via `Database:AutoMigrate`
  (compose sets `DB_AUTO_MIGRATE`, default `true`).

## Testing and Validation

- API: `cd apps/api && dotnet test` (Domain, Application, Infrastructure, Integration).
  Integration tests boot the real `Program` through `FoodeezWebApplicationFactory` with the
  EF **in-memory** provider; `ControllerDependencyTests` proves every controller resolves.
- Shared/web: Vitest (`npm run shared:test`, `npm run web:test`). Web tests run in a `node`
  environment and cover stores and utilities, not component rendering.
- Mobile: Jest + `jest-expo` + `@testing-library/react-native` (`npm run mobile:test`).
- `npm test` at the repo root runs every workspace's tests.
- Type checking: `npm run web:build` runs `vue-tsc` before Vite.
- No linter, formatter, or CI pipeline is configured in this repo.

## Build, Run, and Deployment

- Local: `dotnet run --project src/Foodeez.API` (from `apps/api`), `npm run web`,
  `npm run android` / `npm run mobile`. `npm install` must be run from the repo root.
- `npm run shared:build` before the first web/mobile run (Vite aliases the shared source
  directly, but the mobile Jest mapper and the published package rely on the build output).
- Deploy: `docker compose up --build` - MySQL, the API image (`apps/api/Dockerfile`,
  .NET 10 SDK to aspnet runtime, non-root, `/health` healthcheck), and an nginx image
  (`apps/web/Dockerfile`) serving `apps/web/dist` and proxying `/api/` to the API.
- The mobile app is not containerised (`.dockerignore` excludes it).

See `.claude/workflows.md` for step-by-step procedures.

## Known Gotchas

- **EF Core stays on 9.x.** Pomelo 9.0.0 is the newest MySQL provider and is built against
  EF Core 9; pulling EF Core 10 alongside it breaks `DbContext` construction.
- **Entity ids are client-assigned.** `AppDbContext` sets `ValueGenerated.Never` on every
  `BaseEntity.Id`. Without it, a child added to a loaded parent is tracked as `Modified`,
  saved as an UPDATE of a row that never existed, and surfaces as a phantom 409.
- **AI HTTP clients are not resilience-wrapped, on purpose** - a model call is non-idempotent,
  billed per attempt, and its streaming body cannot be replayed. Spoonacular and USDA *are*
  wrapped (idempotent GETs).
- **Kestrel's minimum response data rate is disabled** (`Program.cs`) so a slow AI stream is
  not aborted mid-thought; nginx correspondingly sets `proxy_buffering off` and 600s timeouts.
- **`Failure(...)` / `ProblemDetails` is the only refusal shape.** Clients read `detail` and
  `title`; a bare string or a `{ message }` body reaches the mobile app as a generic error.
- **Ports differ by document.** `README.md` and `vite.config.ts` say the web dev server is on
  3000; `start-all.bat` prints 5173. Vite's config is authoritative - `Needs verification`
  whether the batch file is simply stale.
- **CORS is wide open in Development only.** Elsewhere `Cors:AllowedOrigins` is empty by
  design, because nginx makes the web app same-origin.
- Push notifications are stubbed - `NotificationService` only logs (TODOs name FCM/Expo Push).
